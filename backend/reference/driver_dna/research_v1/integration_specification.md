## Capture and session ownership

1. Keep one UDP listener. Extend its current parser registrations and provider subscription. Record game release, UDP format, packet version, per-packet session clock, frame and overall-frame ID, selected player index, packet kind, and arrival timestamp. Scope capture to the explicit player. A game session UID is a capture key. An authenticated RaceMind session UUID is an ownership key. Resolve their association at recording start and never infer ownership from an incoming UUID or a broadcast room.
2. Partition by game session and timeline segment. Use overall frame ID to detect arrival order and game frame/time resets to detect timeline discontinuities. Handle explicit flashback events as segmentation points and retire superseded observations from the accepted lap attempt. Duplicate suppression keys include capture ID, timeline segment, frame ID and packet kind. Close a lap when the packet sequence and completion metadata agree. Preserve last-known validity before the boundary and use Session History when available. Conflicting or absent validity becomes unknown with reason. Use the current unique `(session_id, lap_number)` row for the canonical lap and immutable attempt IDs for repeated or superseded attempts.
3. Join packet families by matching game frame where possible and by timestamp within a bounded tolerance otherwise. Record offset and provenance per channel group. Only interpolate continuous channels inside the approved gap and layout segment. Keep flags, gear and event channels discrete. Persist native distance when available. Tag legacy integrated distance as estimated and retain it for intra-lap coaching where appropriate. Use direct distance or validated track-map projection for real-to-game corner matching.
4. Keep `Lap.is_valid` authoritative for existing reports when known. For new captures, record a nullable validity signal and its provenance alongside the existing boolean, including a distinction between game-confirmed valid and a legacy default. Store a user-authored intent annotation separately with revision, timestamp, and source. Support an unreviewed state and an explicit exploration state. User edits update the analysis input revision. A cut, warning, speed drop, spin, and intent remain separate facts.
5. Reuse frame repository queries, per-lap batches and Alembic. Put frequently queried alignment keys in typed nullable columns. Store wider optional motion channels in a versioned capture block keyed by capture and frame, with channel validity and sample quality available at read time. Existing rows load with explicit missing channels. Persist lap completion metadata and the last frame batch atomically. Capture recording is independent of live WebSocket delivery. A cloud ingestion feature would need per-owner capture authorization and storage before it can serve historical DNA results.

The currently published EA 2026 structure attachment documents 24 car slots, a 29-byte header, and `m_overallFrameIdentifier` that does not roll back on flashbacks. At the reviewed commit, the base parser assumes 22 cars, a 57-byte LapData element and a 60-byte CarTelemetry element. The DLC parser assumes 24, 57 and 59 respectively. These match the reviewed layouts for the fields consumed. Both partial decoders currently lack per-packet version checks and associate the most recently received LapData by session UID. Add official-spec byte-fixture tests for both formats, including patch-specific versions, lap crossings and out-of-order delivery. The EA post also advertises a Season 8 PDF revision. Confirm its layout before enabling an untested patch version. The EA base F1 25 PDF specifies menu-selected rates for Motion, Lap Data, Car Telemetry and Motion Ex, with slower or event-triggered cadences for other packet types. Measure effective rate, burst loss and maximum gaps by channel group after decoding and joining. A session-wide receive-rate log mixes packet types and cannot establish the usable sample rate. Treat game brake as a normalized control, steering as a normalized control, and supported Motion Ex values as simulation outputs. Carry assistance status and source through extraction. Physically calibrated brake pressure and steering-wheel angle cannot be recovered from the normalized controls.

## Reference store and release lifecycle

- The CSV and JSON files are the portable exchange format. Load a single immutable snapshot selected by the manifest. Validate the schema, hash and row count for each file, enforce evidence/driver/profile/corner keys, validate feature units and compatibility, and reject implicit zeros, conflicting duplicate keys and disallowed release scopes. Keep the declared schema and dataset versions independent.
- Store an immutable SQLite reference index under the app data directory, with an in-memory immutable snapshot for the hot read path. Use release-scoped indexes by `driver_id`, `profile_id`, `evidence_id`, feature ID and context key. Keep the reference snapshot separate from the user database. Large permitted derived feature partitions may later use Parquet with versioned schema. This release's exchange formats need no large-data dependency.
- Stage an update under a temporary release path, verify its hashes and admission status, build the index, then atomically select it. Read the selected release once at the start of each request. Keep the prior good release for rollback. For a distributed installer, verify signed release metadata from a trusted release key in addition to the manifest's internal checks. The update channel may carry only sources and artifacts cleared for that audience. Raw upstream research material remains outside the released package.
- Load the bundled cleared snapshot and database on local backend startup. An offline request should require the local player session and installed dataset only. A missing or invalid release yields `reference_unavailable`, while an installed catalog with sparse evidence yields `insufficient_evidence`. A network failure during update leaves the previous verified release selected.
- Cache extraction by owned session ID, input revision (accepted attempts, annotations, metadata), and feature-definition version. Cache matching by extraction hash, context selector, reference release, and model version. Keep previous outputs reproducible while their referenced release remains installed. Only include matches or evidence tied to that release in a response.

## Service and API contract

Implement `CoachingService.generate_driver_dna(session_id, options)` as the async orchestration boundary. It loads completed laps, capture coverage, context, and accepted annotation revisions using existing repositories. The feature extractor and matcher are pure functions. The matcher consumes an explicit snapshot and returns an immutable typed result. Suggested interfaces are:

```python
extract_features(
    laps: list[AlignedLap], context: SessionContext, dictionary: FeatureDictionary
) -> FeatureVector

compare_driver_styles(
    player: FeatureVector, references: ReferenceSnapshot, policy: MatchingPolicy
) -> DriverDNAComparison
```

A `FeatureVector` carries `feature_definition_version`, `session_revision`, `layout_version`, `context`, and rows keyed by `(feature_id, corner_id_or_class, context_key)`. Each row carries `value: float | null`, `unit`, `method`, `missing_reason`, `compatibility`, `eligible_lap_count`, `independent_session_count`, `sample_rate_hz`, `capture_quality`, and `uncertainty_interval` when estimated. Attach the included lap attempts and telemetry ranges to the row evidence. `SessionContext` carries game/build/format, car, layout, weather/grip, session type, assists, device, setup identity when available, and tyre/traffic state. Keep scope and validity with each input partition.

A `ReferenceSnapshot` exposes versioned driver, era, team and context profiles, numeric observations with explicit release eligibility, qualitative evidence, and conflict records. Join numeric values only where the compatibility matrix and reference support permit. The comparison result contains eligible candidates, coverage, per-feature contribution and direction, references used, abstention reasons, and coachable player observations. Match and uncertainty logic follows the matching specification. Store raw distance/rank internally for reproducibility. Any user-visible similarity percentage requires a separately validated calibration.

Add authenticated `GET /api/v1/coaching/{session_id}/driver-dna`, using `SessionService.get_owned`. Accept an optional `dataset_version` and `scope` constrained to supported selectors such as `session` or `valid_laps`. Evaluation uses owned server-side data. Return 404 for absent or unowned sessions. Use a typed 200 body for evidence outcomes, including an installed but unsupported dataset profile. An explicit unavailable release selector can return 404 with a stable error code. If computed asynchronously in the future, add an explicit job response and durable key. `GET /api/v1/coaching/{session_id}/driver-dna/evidence/{evidence_id}` should resolve only installed released evidence linked from an owned report or return 404. Provide public source title, publisher, date, URL, scope and limitations, with no media payloads. Use the same route for local and cloud clients where the backing session exists.

```json
{
  "schema_version": "1.0",
  "status": "insufficient_evidence",
  "dataset_version": null,
  "feature_definition_version": null,
  "model_version": null,
  "scope": "session",
  "reason_codes": ["NO_PLAYER_TRACE", "INSUFFICIENT_ELIGIBLE_REFERENCE_FEATURES"],
  "coverage": {
    "valid_lap_count": 2,
    "exploration_lap_count": 2,

  },
  "personal_best_ms": 92495,
  "personal_best_basis": "scenario_metadata",

```

The JSON is illustrative for the Suzuka brief. The numeric result is the supplied best lap, conditional on a valid recorded lap confirming it. In a production response, actual loaded dataset and feature versions are required when those resources are present. With two eligible candidates, return `status: "matched"`, `driver_id`, `profile_id`, context scope, ordinal rank, eligibility coverage, confidence tier and reason codes, observed directions, matching and differing trait arrays, and evidence references. Keep the secondary match null if it fails support or rank-stability checks. An `ambiguous` result may list qualified candidates with unresolved ordering and leave the primary/secondary fields null. Include a distinct `reference_unavailable` status for an uninstalled or failed reference snapshot.

## Desktop and coaching presentation

- Extend the current coaching API query to include `session_id`, release and revision in its cache identity. Display primary and secondary profiles only if eligible, with the team, season and condition attached. For an abstention show the specific evidence gap and which player-only observations remain available.
- Open each displayed contribution in the actual distance-aligned trace and show lap attempts, source units, distance basis, trace quality, validity and intent. Render uncertain intervals and missing series as gaps. A named corner requires the supported game layout and validated mapping. Retain generic corner-order labels when mapping is unavailable.
- Present a player practice objective from their repeatable valid-lap losses, linked to measurable behavior. Report personal deltas in physical units. Cite the comparison source for qualitative resemblance and identify it as such. Include game build, assists, setup and input device when relevant to interpretation.
- Generate AI Engineer input from this typed result after checking session ownership. Allow the LLM to summarize approved observations and confidence reasons. Driver choice, invalid-lap cause, and numeric deltas come from the backend. Radio delivers requested short coaching cues with the existing throttle and priority. Driver DNA processing stays outside live decision latency.

## Implementation and acceptance sequence

1. Add replay-compatible capture metadata, record lap validity and integrate local frame/lap persistence. Verify parser fixtures across both formats and each enabled packet version, nonzero player indexes, invalid boundary timing, duplicates, frame gaps, zero clocks, flashbacks, player switch, reconnect, and legacy recordings. Exercise local SQLite and cloud Postgres only where storage is supported.
2. Add layout resolution and the shared typed feature extractor. Verify actual game traces against known corners before exposing named-turn deltas. Reconcile source and integration distance on representative clean laps, and verify degraded behavior for legacy files and missing motion or assist channels.
3. Import release artifacts and add the authenticated API. Test duplicate evidence IDs, incompatible feature units, absent references, wrong ownership, rollback, air-gapped reads and in-flight refreshes. An unknown, future or untested packet version should be observable in capture diagnostics and ineligible for the affected DNA metrics.
4. Add player feedback and abstention-first presentation. Confirm that no ranked result appears when no permitted empirical reference rows meet the policy. Validate ranking on held-out driver sessions and player cohorts, then run a separate audit before enabling cross-domain ranked output. Include a mixed-validity Suzuka scenario in acceptance, with identical eligibility behavior for the desktop and AI Engineer.
